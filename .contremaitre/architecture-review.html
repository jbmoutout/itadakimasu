Problem: Two PrismaClient instances with different configs compete. Connection pool doubles; query logging is inconsistent.

Solution: Delete app/lib/prisma.ts. All routes import from the canonical @/lib/prisma alias.

  • Locality: one DB config, one connection pool
  • Leverage: consistent logging everywhere
  • Delete 10 shallow re-imports

Problem: 4 routes ignore x-user-id from middleware; any authenticated user can read/write any other user's data.

Solution: Add getUserId() call or wrap each handler with a withAuth() factory that injects userId.

  • Locality: auth enforcement at each seam
  • Leverage: one wrapper pattern, 4 call sites fixed
  • Eliminates cross-user data access vector
ADR-0001 alignment: middleware already enforces auth at ingress. This candidate closes the gap where handlers ignore the trusted header — it completes the ADR, not contradicts it.

Solution: Extract planner-service, scoring, prompt-builder, and response-formatter into separate modules. Route becomes a thin orchestrator.

  • Test scoring & formatting without HTTP

Top recommendation

Consolidate the Prisma client seam — it's the cheapest, safest, highest-impact win.

Two singleton files is a bug that compounds daily. Every new route imports one or the other, widening the gap. Deleting one file and fixing the imports takes minutes, eliminates the connection-pool doubling, and makes logging uniform. It also removes a recurring source of WTF for every developer who discovers the two files.

Closely followed by the weekly planner deepening and the ingredient aggregation extraction, which unlock testability and eliminate copy-paste debt respectively.
