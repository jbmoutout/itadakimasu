One singleton, environment-guarded logging

Problem

Two Prisma singletons with inconsistent logging, raw SQL in 7 functions that bypass typed API.

Solution

Delete app/lib/prisma.ts, port weekly-plan-history.ts to typed Prisma client, add dev-only logging guard.

Wins

  • locality: one import path for all Prisma access
  • leverage: typed API replaces 7 raw-SQL call sites
  • interface shrinks; no surprise-logging in prod
  • deletion test: two files become one

Planner reads from SavedIngredient; dead routes & model removed

Problem

ShoppingList JSON-blob model duplicates SavedList/SavedIngredient; planner reads checked items from dead storage.

Solution

Delete ShoppingList model, its two routes, and port planner context to SavedIngredient.checked.

Wins

  • locality: one model family for shopping state
  • deletion test: 2 routes + 1 model + raw SQL vanish
  • leverage: planner context is just a Prisma query
  • data integrity: no desync between checked states

One seam with three named operations; Anthropic adapter swappable

Problem

Three route handlers each build AI prompts, call Anthropic, parse responses, and handle errors independently.

Solution

Extract a lib/ai-pipeline.ts module exposing generatePlan(), extractIngredients(), generateAlternatives() behind one Anthropic adapter.

Wins

  • locality: prompt schema, retry, error handling in one place
  • leverage: one interface for 3 call sites + future AI features
  • interface shrinks; route handlers become request-parsers only
  • testability: swap Anthropic for in-memory adapter
  • eliminates extractor.ts duplication

Problem

Recipe scoring is not testable independently — it's embedded inside a 280-line component alongside rendering logic.

Solution

Extract scoreByIngredientOverlap(recipes, checkedIngredients): ScoredRecipe[] as a pure function module.

Wins

  • locality: scoring logic concentrates in one pure function
  • leverage: one interface, unit-testable without React
  • deletion test: scoring moves from 280-line component to 30-line module
  • reusable: planner alternatives could consume same scorer

Top recommendation

Consolidate the Prisma access seam — it unblocks every other deepening. Until the data-access seam is unified, the AI pipeline extraction, legacy model cleanup, and any new feature all risk importing from the wrong prisma.ts or reaching for raw SQL. One singleton with environment-guarded logging, then port the 7 raw-SQL functions to typed Prisma API. This single change produces the highest leverage-to-effort ratio in the codebase.
